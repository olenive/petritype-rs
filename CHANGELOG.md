## 0.3.0, 2026-11-23

The [`v0.3.0` tag](https://github.com/olenive/petritype-rs/tree/v0.3.0). A minor version, since closed nets can break a program: the two entries marked as such say what a program changes.

- `petritype-runner`'s `protocol::ErrorCode` reads an error code it does not know as `ErrorCode::Other(name)`, keeps it and writes it back unchanged, and the rest of the answer is read, so that a later runner's new code reaches a client as a failed request with that code (PROTOCOL.md §3). A client built on 0.2.x cannot read an answer with `closed_net` at all. `ErrorCode` is no longer `Copy`, and `ErrorCode::as_str` borrows.
- **A change that can break a program: closed nets** (stage one, DESIGN §6.9). A net that marks any place as a port is now closed: from outside it (a body of the net around it holding it as a token by any edge, the program and its drivers, the runner's `inject`), tokens are put, taken, removed, replaced or set only at its ports. A net that marks no port stays open. Its own transitions, the handlers of its own controls (`Net::press`), its seeds, a firing's outputs, a failed firing's restore, imports, forks and deep steps are inside, and a write at a window (the place a net has for a port of one of its subnet places) is judged by the holding net's rule first. A refused write is `NetError::ClosedNet { net, place, act }`, and there are three ways to make it land: mark the place as a port, start the net with the token in its definition (a seed or a template's token), or declare the net open with the new `NetBuilder::open`. `Net::is_open` reads the declaration and `Net::is_closed` the rule's answer. `remove`, `replace` and `apply` of a `Command` (and so `apply_json`) return the error; `put`, `extend` and `set_tokens` keep their signatures and panic with its message, and the new `Net::try_put`, `Net::try_extend` and `Net::try_set_tokens` return it. A body that is refused fails its firing with the error, not `BodyPanicked`, even when it dropped the `Err` or caught the panic, and the firing restores what any failure restores; a firing that took a token carrying a net cannot restore it (`RestoreOfNoClonePlace`), so a refused one loses it.
- **A change that can break a program: a body's knobs.** A body that holds a net marking a port, closed or declared open, is refused setting its parameters, switches, tie-break, stepping rules and selector, firing it by name (`fire`, `launch`, `distribute`, `step_inside`), pressing its controls and importing a marking into it, as `NetError::HeldByBody { net, act }`; `set_tie_break`, `set_selector`, `clear_selector` and `step_inside` panic with its message, `press` answers `PressError::Refused` with it, and the firing fails with the error. The program, its drivers and the runner keep all of them on any net, and a body on a net with no port keeps them in stage one. Reading and stepping (`step`, `step_deep`) stay allowed for everyone. Stage two, announced and not built, will close every net that does not declare itself open and refuse a body the knobs of every net it holds: a setting a body makes today on a net with no port then goes to a transition of the net's own, or is left to the program.
- `petritype-runner` answers an `inject` outside the ports of a closed net, at the top level and by path, with the new error code `closed_net` (`ErrorCode::ClosedNet`), and writes `open: true` on the topology of a net that declares itself open (`protocol::Topology::open`; code that builds one by struct literal adds `open: false`). The protocol stays version 2. A client of another runtime sees a code it does not know, which PROTOCOL.md §3 tells it to treat as a failed request; `ErrorCode` is a closed Rust enum, so a program on petritype-runner 0.2.x's `protocol` types cannot read an error line carrying `closed_net`. The example binary carries the conformance net `post-office`, and the shared transcript `19_closed_nets.json` replays.
- An input edge may name the ports it reaches in the nets its tokens carry: `.reaching(["Orders In"])` on every edge kind gives a `Reaching<E>`, which reads, takes or lends as its edge does. The names are on `EdgeInfo::Input::reaches`, `TransitionInfo::reaches` and `TopologyTransition::reaches` (with `serde`, written only when some edge names one). A declaration only, like a group: it changes nothing about firing, and a name the token's net does not have is not checked yet. New build errors `ReachIntoNoNets`, for a reach on a place whose tokens carry no nets, and `EmptyReachName`. `EdgeInfo::Input` gained a field, so code that builds one by struct literal adds `reaches: vec![]`.
- `petritype-runner` writes `port: true` on the port places of every net's topology, the loaded net and a net a token carries as well as a subnet; until now only a subnet's showed them. An input edge carries `reaches` when it names some (`protocol::Edge::reaches`). The protocol stays version 2. The `protocol` types pass over an edge field they do not know and read the rest, as they always have: petritype-runner 0.2.x reads a topology that carries `reaches` and drops it, while Python's wire models up to 0.4.1 refuse it. The example binary carries the conformance net `trays`, and the shared transcript `18_ports_on_a_token.json` replays.

- Read edges: `ReadEdge(p)`, `ReadWhereEdge(p, filter)` and `ReadAllEdge(p)` lend the body the front token, the oldest token a filter accepts, or every token (zero or more), as `&T`, `&T` and `Vec<&T>`, to look at where they lie. No `Clone` is asked of the token type, so they read a `place_no_clone` place and a place of net-carrying tokens, whose nets keep their ids. - Subnet places saved, restored, forked and snapshotted with the net around them, at any depth. A subnet built through a template is stamped; in a marking its place's entry is a list of one, the subnet in its saved form (`template`, `marking`, `params`, `enabled`), and a port's tokens are written once, in the subnet's marking. An import fills the subnet already there, after checking the entry was saved from the template that built it, decodes every level before it changes anything, and lifts each subnet's own `Resynced` before the net's. A fork copies each subnet as it copies the net. A subnet built without a template runs, and the net around it then has no saved form: `NetError::CannotSaveSubnet` and `CommandError::CannotLoadSubnet` name the subnet place and carry why. `NetError::HoldsSubnet` is removed. A snapshot holds a snapshot of each subnet, read with `Snapshot::subnet`, and needs no template for it. Nets without subnet places save to the same bytes as before.
- Reading subnet places: `Net::port_ref::<T>(subnet, name)`, and `PlaceInfo` and `TopologyPlace` gain `subnet`, `port` and `port_of`: a subnet place, a place its own net marked a port, and the outer net's place for a port, naming its subnet place. With `serde` the topology writes each only when set.
- `FiringFailed::path` is a list of `PathStep`s, `Token { place, token, net }` for a token's net and `Subnet { place }` for a subnet place's subnet, so a failure inside a subnet names every level; it was `Vec<(PlaceId, TokenId, String)>`. `OnFailure::Disable` follows a path into a subnet, and a run's `RunSummary::fired_count` counts a subnet's firings, which it missed.
- The `levels` example: a world of two levels built from one template, heroes entering each through its `Lobby` port and leaving through its `Exit Hall` port, saved part of the way and restored.
- The stepping rule per place: each place that holds nets says how they take their turns beside the net around them, `Stepping::InnerFirst`, `TakeTurns`, `OuterFirst` or `Passive`, set with `NetBuilder::stepping` or `Net::set_stepping` and read with `Net::stepping` and `PlaceInfo::stepping`. One deep step tries the inner-first places' nets, then the ring of the net and its take-turns places' nets, then the outer-first places' nets, and a net's turn is a deep step of its own, so every level follows the rules of its own places. `step_deep`, `step_deep_staged`, `step_inside`, both drivers, their fuse and the runner follow it. `Net::fork` copies the rules; a saved net does not carry them.
- The default is now inner first: the nets in a nested place fire until they are at rest before the net around them fires. It was outer first. A net written around outer first states it on its places, as the `transit` example now does; its journey and the shared transcripts are unchanged.
- Removed: `DeepPolicy`, `NetBuilder::deep_policy`, `Net::set_deep_policy`, `Net::deep_policy`, `NetBuilder::passive` and `PlaceInfo::passive`; `TopologyPlace::passive` is `TopologyPlace::stepping`, written by its protocol name. `BuildError::NotNested` is now for a stepping rule on a place that holds no nets, and `NetError::NotNested` is `set_stepping`'s refusal of one. The runner writes the rule on the wire as `stepping` (protocol version 2).
- `petritype-runner` serves a net the host program owns. A program that builds a net and fires it from its own code (a game, a simulation) gives it to a `HostServer`, which listens on a TCP port; any number of viewers attach and are told what the program does to the net, inner nets included. `Host` is the same without the listener, for a program with a transport of its own. The connection reads the net and nothing else: `load`, `reset`, `shutdown`, `step`, `start`, `stop`, `inject`, `enable`, `disable`, `set_param`, `press` and `set_filter` are `unsupported`.
- A host nobody is listening to does none of the work of telling: while no viewer has made its first request, a `HostServer`'s `change` makes no lines and compares no fireable set, and keeps the log, the progress and the marking version as before. `Host::set_listening` is the same switch for a program with its own transport; it is on unless turned off.
- `petritype-runner` speaks protocol version 2, and reads no version 1. An inner net's `path` is a list of steps, `protocol::PathStep` (`{"place", "token", "net"}` for a token's net, `{"place"}` for a subnet), wherever a path is read or written, and `[]` is the loaded net, so every name can be spelt, `/` and `#` included. A path of the wrong shape is `invalid_params`, read before anything is resolved, and one that names no live net is `unknown_net`; both messages name the step by its index from 0. Progress is per net: the outer net's progress counts its own firings only, and the firings inside its tokens are counted in their own nets'. The transcript harness drops the `<path>` mask and substitutes a capture whole only.
- `petritype-runner` writes each place's stepping rule as `stepping` on every place that holds nets, the default `inner_first` included, by its protocol name (`inner_first`, `take_turns`, `outer_first` or `passive`, `protocol::Stepping`), and no longer writes `passive`. The example binary carries the conformance net `stepping-rules`, and the shared transcript `10_stepping_rules.json` over it replays.
- `petritype-runner` serves subnet places (PROTOCOL.md §12.7), and `load` no longer refuses a net that holds one. A subnet is one more inner net, addressed by the step `{"place"}` at any depth, with its own version, topology, progress, log entries and fireable set from `load` or `reset` until the next. The topology writes a subnet place as `{name, type_name, subnet: true, ports, stepping}`, its template as its `type_name`, and an edge on a port with `port` beside `place`; a subnet's own topology marks its ports `port: true`. In `get_state` a subnet place's entry is `{subnet, ports}`. Wherever the net around a subnet names a port, `port` stands beside `place` (`added`, `removed`, `mutated`, `hidden`, `get_place_tokens`, `inject`, a `query` match), and a position names it by `{"place", "port"}` (`consumed`, `produced`, the log): `protocol::PlaceName`, which a filter's and a `distinct`'s `places` take too. A port is projected by its subnet's filter in both views. A change of a port raises both nets' versions, and the notification carries the other's as `subnet_marking_versions` or `outer_marking_version`; both nets' fireable sets are compared after it, the shallower first. A read of a subnet waits while an outer firing on one of its ports is in flight. Protocol types that change: `Notification`'s token and firing variants (`port`, the two version fields, `consumed` by `PlaceName`), `Produced::place`, `LogEntry`'s pairs, `Filter::places`, `Place` (`serializable` is optional, absent for a subnet place, and `subnet`, `ports` and `port` are new), `Edge::port`, `PlaceTokens::port`, `QueryMatch::port`, and `Marking::places`, whose entries are a `PlaceEntry`. `get_token` takes an id in its canonical form only. The shared transcript `09_subnet_places.json`, over the conformance net `levels`, replays, and the transcript harness folds the two version fields from both pieces of a firing.
- `petritype-layout` lays out a subnet place as one node: a box with rounded corners, sized for a small circle per port with its count beside it, its name as the title and the count inside, which ranks and orders as a place would, an edge on a port counting as an edge on the box. Each port's circle is on the side of the box facing the transitions it joins, ordered by where those transitions are. The places a layout is given are `LayoutPlace`s, an id, a name and a `PlaceKind` (`Ordinary`, `Subnet`, or `Port` of a subnet place); `compute` reads the kinds off the net, and `compute_named` and `compute_subgraph` take anything that turns into a `LayoutPlace`, a `(PlaceId, String)` still being an ordinary place. New: `Layout::subnet_box` (a `SubnetBox` with its centre, size, corner radius, the room for its title and count, and a `PortCircle` per port), `Layout::radius_of_place`, and `Layout::port_radius`, 14 by default as a ghost's. `position_of_place` answers for a port with its circle's centre, `half_extent` with the box or the circle, and `placement` with `None`, a port being no node of its own. A net with no subnet places lays out to the same numbers as before.
- `petritype-dot` draws a subnet place as one box with rounded corners (`shape=Mrecord`, `fillcolor=lightskyblue`), titled with the place's name, with a cell per port in the subnet's order showing the port's name and count (the name alone when `Style::show_tokens` is off). The cells are named `port0`, `port1`, ... by position, and an outer edge on a port ends at its cell, `tailport` for an input edge and `headport` for an output edge; the ports are not drawn as nodes of their own, and the other places keep their `p<i>` ids. The box is outlined when the highlighted firing touched one of its ports. In a subnet's own drawing a port place has a second ring, `peripheries=2`. A net with no subnet places draws to the same text as before.
- Groups, a label on parts of a net that only drawings read: `NetBuilder::group(name) -> GroupRef` declares one, `NetBuilder::in_group(group, place)` puts a place or a subnet place in it (through `PlaceHandle`), and `TransitionBuilder::group(group)` a transition where it is declared. A node is in one group or in none, groups keep their declared order, and a subnet or a net carried by a token has groups of its own; the place a net has for a port is in none. Read with `Net::groups` and `Snapshot::groups`, `PlaceInfo::group` and `TransitionInfo::group`, and in the `Topology` as `groups`, with `group` on `TopologyPlace` and `TopologyTransition`, each written with `serde` only when set. New build errors `DuplicateGroupName`, `PlaceInTwoGroups`, `TransitionInTwoGroups` and `PortInGroup`; a group handle from another builder panics. Firing, stepping, ids, saving and the events are those of the same net with no groups, and a net with no groups writes its topology and saves to the same bytes as before. The `hike` example: a walker whose walking and eating both change its energy, each concern a group and the energy in none.
- `petritype-dot` draws each group as a Graphviz cluster, `subgraph cluster_<n>` in declared order with the group's name as its label and `style=dashed`, holding the group's places, a subnet place with its box, and then its transitions; the nodes in no group come first, at the top level. `DotSource` has a new method, `groups`. A net with no groups draws to the same text as before.
- `petritype-runner` serves groups (PROTOCOL.md §5.1): a net's topology lists its groups as `groups`, in declared order, and the `group` of each place, subnet place and transition in one, each written only when set, for the loaded net and every inner net, each its own; a port listed in a subnet place's `ports` carries no `group`, its group being the subnet's. Nothing else on the wire changes, and the protocol stays version 2. New fields `protocol::Topology::groups`, `protocol::Place::group` and `protocol::Transition::group`. The example binary carries the conformance net `groups`, and the shared transcript `11_groups.json` over it replays.
- `petritype-layout` lays out groups in place of clusters by name prefix. Removed: `Clustering` with `Clustering::NamePrefix` and `prefix_of`, `Layout::clustering`, `Layout::with_clustering`, `Layout::display_name`, `Layout::cluster_names`, `Layout::cluster_bounds` and `Layout::cluster_of`; no name is split or shortened. `Layout::cluster_gap` is `Layout::group_gap`. `LayoutPlace` gains `group` and `in_group`, and transitions are given as the new `LayoutTransition` (an id, a name and a group), which a `(TransitionId, String)` or a `(TransitionId, TransitionInfo)` turns into; `compute` reads the groups and their declared order off the net, and `compute_named` and `compute_subgraph` take the order as a new `groups: &[&str]` argument. An open group is laid out on its own in a frame, as a cluster was, and the nodes in no group are one block with no frame, packed before the groups. A group named in the new `Layout::closed` (or `Layout::with_closed`) is one box among the nodes in no group, which ranks with them: its members are hidden, an edge inside it is not drawn, and the edges in one direction between the box and one node, or two boxes, are one merged arrow. New: `Layout::group_names`, `group_bounds`, `group_of`, `is_group_closed`, `group_box` (a `GroupBox`), `hidden_in`, `merged_arrows` and `merged_arrow_for` (a `MergedArrow` between two `ArrowEnd`s, with the edges it stands for and whether it is a back-edge), and `group_ghosts` and `group_ghost_position` for the one ghost a ghosted place gets beside a closed box on each side it needs. A focused part (`compute_subgraph`) names groups where it named clusters, and draws a focused group open whatever is closed. A net with no groups lays out to the same numbers as before, and a net whose every node is in an open group to the numbers of the same net clustered by prefix.
- `petritype-activity` reads groups: a `Grid` packs the nodes in no group first and then the groups in the layout's order, and a node hidden in a closed group gets no cell.
- `petritype-runner` reports the time an inline body took. A firing inside an inner net, a body with a mutate edge, and a `press` run on the owner's thread, inside the call that fires them, and the `duration_ms` of such a firing, in its `fired` and in its log entry, a failed firing's log entry included, is now the time that call took, read off a stopwatch; it was 0. A press gives its time to the one firing it made, when it made one. A firing a body makes inside the nets of the tokens it holds carries 0, its time being part of that body's. Nothing else on the wire changes.
- The `petritype-runner` example binary carries four more conformance nets of PROTOCOL.md §11, `workshop`, `cellar`, `harbour` and `odd-names`, and the shared transcripts over them replay with nothing on the wire changed: `12_failures.json`, failed firings that lose their token and that give it back, from a place and from a port, with `workshop`'s load parameter `restore`; `13_ports_from_outside.json`, a subnet's port read, changed and filtered by the net around it; `14_subnet_in_a_token.json`, a subnet inside a net that a token carries, as the token moves and when it is consumed; and `15_odd_names.json`, names that hold a slash, a hash, a space and a double quote. A shared transcript masks a failure's `error` text, which each runtime words its own way, and the harness's string masks match it with no new rule.
- `petritype_runner::main` takes `--net <name>`, with `--describe` or without: the binary carries the one net registered as `<name>` and no other, so that `describe` lists it alone and `load` knows no other. A shared transcript of PROTOCOL.md §11 is recorded against a runner carrying its own net alone and may pin `describe` in full, so this is how a host replays one against a Rust binary over pipes. A name the binary does not carry exits 2 with a message on stderr naming the nets it carries. The runner's tests replay every shared transcript in `tests/protocol/` over real pipes against the example binary started that way.

## 0.1.0, 2026-10-23

The first release, early: the API will change.

- `petritype`, the core crate: typed places, transitions whose bodies are plain functions, eight kinds of input edge (take, take all, snapshot, mutate, keyed take and mutate, drain and survey), and outputs by position, by name (`#[derive(Inputs)]` and `#[derive(Outputs)]`), by type (`#[derive(Routed)]`) or as an explicit `Distribution`.
- Firing inline (`step`, `fire`) or in three stages (`launch`, `run`, `distribute`) so that bodies may run on other threads; a body's `Err` or panic fails the firing, with optional restoring of the consumed tokens. The `drivers` module runs a net to quiescence or on a clock, sequentially or with bodies on threads.
- Every change is an event, and every token has a stable id. Commands feed a running net from another thread, `Param::<T>` values are set per run, `net.snapshot()` hands another thread an owned copy, and `assert_acyclic` and `assert_no_source_transitions` check a net's structure when it is built.
- Nets as tokens: a token may carry nets of its own, which the outer net runs and logs. Token keys, queries and filters: a place derives keys from its tokens and the net answers queries from an index. Net-declared controls and token styles.
- With the `serde` feature: commands as JSON, and a net saved and loaded as JSON, its tokens' inner nets rebuilt from templates registered by name.
- `petritype-dot` draws a net or a snapshot as Graphviz DOT; `petritype-layout` lays a net out for any renderer; `petritype-activity` tracks a net's activity and draws its activity thumbnail.
- `petritype-runner` serves a net over the net protocol (version 1) on stdin and stdout, and replays the protocol transcripts shared with the Python runtime.
- Examples that port the Python acceptance set, each also a test, and the conformance nets `transit`, `wildlife`, `shop` and `traffic-light`.
